Packages and ROS API

robomaster_ros2 contains the hardware server, parameter server, network helpers and device drivers. robomaster_interface defines their custom messages and services. robomaster_examples supplies waypoint/trajectory examples, fleet diagnostics and joystick control. Simulation is documented separately in Simulation.

Namespaces and availability

The server uses root fleet services. Each device node is created in its own namespace: a device named rmtt_1 has node name /rmtt_1/rmtt_1 and topics such as /rmtt_1/image. Replace <name> below with the configured name. Sensor flags and detected model capabilities control endpoint creation; not every robot provides every endpoint.

Topics and units

The endpoint is /<name>/<topic> unless stated otherwise. Standard message names below come from geometry_msgs/msg or sensor_msgs/msg; named RoboMaster messages come from robomaster_interface/msg.

Device / topic

Message

Direction / semantics

Both: image

sensor_msgs/Image

Published raw bgr8 frames; best-effort, volatile, depth 1.

Drone: cmd_vel

Twist

Subscribed normalized RC inputs in [-1, 1]; not m/s or rad/s.

Drone: front_tof, bottom_tof

Range

Enabled distance sensors.

Drone: attitude

QuaternionStamped

Enabled attitude telemetry.

Drone: baro, imu, mpad

FluidPressure / Imu / TelloMpad

Optional telemetry; barometer/IMU unit handling remains incomplete.

Pose

Subscribed chassis translation in m/s and yaw in rad/s.

Gimbal: gimbal_angle

EP Core: arm_cmd_vel

Twist

Subscribed X/Z stream velocities in m/s; independent of the motion gate.

EP Core: arm_position

PointStamped

Enabled legacy arm DDS feedback; service command units must not be inferred from this topic.

EP Core: arm_action_status

ArmActionStatus

Tracked service action ID, state, progress and completion.

EP Core: gripper_state

GripperState

Hardware endpoint status plus estimated percentage, mode and operation state.

Armor: armor_hit, ir_hit

ArmorHit / IrHit

Event topics; silence can be normal.

External pose subscriptions use the configured ext_pose_topic_name and ext_pose_topic_type. There is no fixed external_position input topic. The real driver does not create a positioning system from these settings.

Camera publication is direct; the driver creates no compressed image topic or camera bridge. Most other topics use reliable QoS. Arm velocity uses depth 20 and gimbal velocity depth 60. See Using the hardware driver for lifecycle/units and Fleet diagnostics and joystick control for current example limitations.
